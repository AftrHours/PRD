## 1. Feature Name

**Latest Read**

The most recently read book is shown prominently on the Library page as a **Continue reading** card, separate from other books. One tap opens it at the same reading position as when it was last left. This story also owns the progress log that stores each book's reading position.

**User story**

> As a **reader**, I want to **see my latest read** so that I can **easily find the book I have imported**.

---

## 2. Problem

1. **Losing the reading position.** Readers with aphantasia already struggle to keep story context in mind; a lost or inexact position on return adds to that load.
2. **Page numbers aren't stable.** On screens that rotate, resize, or change font size, page numbers shift, so a position saved as a page number can't be trusted.
3. **The current book gets buried.** As the library grows, readers have to search for the book they're in the middle of.

---

## 3. Goals

**Goals**

1. The latest read is **easy to spot** on the Library page and **separate** from other books.
2. Opening a book (from the card or the library) always returns to **the same reading position**: with the same layout the visible page starts at the same paragraph and offset, including after the app is fully closed; after a font, orientation, or window size change, the last-read paragraph is on the visible page.
3. Progress is saved **automatically**, with no action from the reader.
4. Provide an accurate `readingFrontier` for the Epic 2 anti-spoiler rules.

**Non-goals (this release)**

- Reading session history (duration, daily stats). (\*)
- Syncing the reading position across devices. (\*)
- Manual bookmarks and highlights. (\*)
- Several "Continue reading" cards at once. (\*)

## 5. Main Flow

### 5.1 User flow

```mermaid
flowchart LR
  A([Start: Revisit the app]) --> B[Library page<br/>Latest Read highlighted]
  B --> C[Reading page<br/>exact same position]
  C --> D([End: Reading page])
```

| # | Screen | See | Do | System response |
|---|---|---|---|---|
| 1 | Library page | **"Continue reading"** card at the top, separate from the book list: large cover, title, author, current chapter ("Chapter 3: The Harbour"), progress (%), time last read ("2 hours ago"). Other books appear below. | Tap the card | Reading page opens |
| 2 | Reading page | The same page as when last left: the same paragraph and sentence are on the visible page | Keep reading | Progress keeps being saved (§5.4) |

### 5.2 Latest Read rules (\*)

- **Latest Read** = the unfinished book with the most recent `lastReadAt`.
- **Finished** = the reader has shown the book's last page, or `progress ≥ 0.99`.
- The card only shows if some book has been read and isn't finished. Otherwise the card doesn't show and the book list sits right under the header.
- The book in the card also stays in the library list (so sort order stays consistent), with a small "Reading" marker.
- If the book in the card is removed (PRD 1.2 §5.4) or finished, the card shows the next unfinished book with the most recent `lastReadAt`; if there is none, the card disappears.

### 5.3 Progress log (\*)

One `ReadingProgress` per book, stored in `Books/<bookID>/progress.json`.

| Field | Content | Purpose |
|---|---|---|
| `bookID` | Book ID | Key |
| `position.paragraph` | Global paragraph index (from `BookContent`) | Reading position independent of screen or font size |
| `position.charOffset` | Character offset in the paragraph (UTF-16) of the first word on the visible page | Exact position inside long paragraphs |
| `chapterIndex` | Chapter index | "Chapter X" label on the card |
| `progress` | 0–1, words before the position / total words | Percentage on the card and in the library list |
| `lastReadAt` | Timestamp of the last page change | Decides Latest Read |
| `readingFrontier` | Index of the furthest sentence ever shown on screen. Pre-rendered or prefetched pages that are not visible do not count; on iPad, all pages visible at once (for example a landscape two-page spread) do. (\*) | Epic 2 anti-spoiler boundary, including story updates (PRD 2.1 §5.4, §5.4.1) |
| `finishedAt` | Timestamp the book was finished, or empty | Decides whether the book still counts as Latest Read |

`lastOpenedAt` (used by the Recent sort in PRD 1.2) isn't part of the progress log; it lives in `BookRecord` and is updated by `ReaderVM` (through `LibRepo`) every time a book opens.

### 5.4 Saving and restoring the position

**Saving**
- On every page change: update `position`, `chapterIndex`, `progress`, `lastReadAt`; `readingFrontier = max(readingFrontier, last sentence on the pages visible at that moment)`. Disk writes run off the main thread and are coalesced (one write at a time, always the latest state), so a force quit loses at most the last page turn. (\*)
- When the app goes to the background or the book closes: write immediately (no debounce).
- Writes are atomic so the file isn't corrupted by a force quit.

**Restoring**
1. Load `ReadingProgress`; if there is none, open at the start of the book.
2. Paginate for the current screen size and font.
3. Find the page containing `(position.paragraph, position.charOffset)` and show it.
4. If the position is invalid (for example `BookContent` was rebuilt and paragraphs changed), open at the start of chapter `chapterIndex` and log `restored_ok = false`.

**Relation to Jump back (Epic 2)** (\*)
- When the reader uses Jump back, the saved position follows the page being shown, while `readingFrontier` doesn't move backwards.
- The origin for "Back to where I was" is stored by Epic 2 in `BookState.returnPosition`, so that button still works after the app reopens.

### 5.5 Components (MVVM)

The app follows MVVM (PRD 1.0 §3.4).

| Layer | Component | Responsibility |
|---|---|---|
| Model | `ProgRepo` / `ProgRepoFile` | Saving and loading `ReadingProgress` (§5.3, §5.4), coalesced writes, atomic writes |
| Model | `FrontierRule` (pure rule) | The `readingFrontier` rule of §5.4: `max(readingFrontier, last visible sentence)`, never moving backwards |
| Model | `PagerSvc` (implementations named `PagerSvc<Variant>`) | Pages for the current font and viewport; turns `(paragraph, charOffset)` into a page and back |
| Model | `LibRepo` | Updates `BookRecord.lastOpenedAt` |
| ViewModel | `ResumeCardVM` | State: `card` (cover, title, author, chapter label, progress %, relative time) or none, per §5.2. Intents: `onAppear()`, `cardTapped()`. Sends `LB_Book_Tap` (source = latest_read). |
| ViewModel | `ReaderVM` (reading part) | State: pages, current page, footer (chapter, %). Intents: `onAppear(viewport:)`, `viewportChanged(_:)`, `pageChanged(_:)`, `fontSizeChanged(_:)`, `scenePhaseChanged(_:)`, `closeTapped()`. Restores the position on open, reports every page to `ProgRepo` (through `FrontierRule`), flushes on background. Sends `RD_Position_Restore` and `RD_Book_Finished`. |
| View | `ResumeCardView`, `ReaderView`, `PageView` | Layout from §5.1; every action calls a ViewModel intent |

The shared data model is in PRD 1.0 §3.

## 8. Open Questions & Risks

1. **Progress log contents (TBD on the sticky note).** The proposed fields in §5.3 need confirmation, especially whether to keep session history for other metrics.
2. **Latest Read marker.** Design decision needed: a large separate card at the top (this document's proposal) or only a badge in the list. The sticky note asks for it to be easy to notice and separable from other books. (\*)
3. **Definition of "finished".** Books with long back matter (notes, glossary) may never reach the last page. Test whether the 0.99 threshold is enough. (\*)
4. **Re-parsing changes paragraph indexes.** If the parser is updated and `BookContent` is rebuilt, an old `position.paragraph` can shift. A parser version in `BookContent` and a position migration are needed. (\*)
5. **Page layout on iPad.** No PRD yet says whether the reader shows one page or a two-page spread in landscape, or how Split View / Stage Manager change the page. This decides how many sentences count as visible for `readingFrontier` (AC-1.3-08, AC-1.3-09). Design decision needed. (\*)
6. **Own paginator (decided).** `PagerSvc` is built in-house (Index §6), so pagination, font changes, and iPad window changes are our responsibility; they are covered by AC-1.3-03 and AC-1.3-04. (\*)
