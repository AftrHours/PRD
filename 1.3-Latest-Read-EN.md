## 1. Feature Name

**Latest Read**

The library sorts by **Latest Read** by default, so the most recently read book comes first. One tap opens it at the same reading position as when it was last left. This story also owns the progress log that stores each book's reading position, and the reading page. A separate **Continue reading** card was planned but **isn't built** (§5.2).

**User story**

> As a **reader**, I want to **see my latest read** so that I can **easily find the book I have imported**.

---

## 2. Problem

1. **Losing the reading position.** Readers with aphantasia already struggle to keep story context in mind; a lost or inexact position on return adds to that load.
2. **Page numbers aren't stable.** On screens that rotate, resize, or change font size, page numbers shift, so a position saved as a page number can't be trusted.
3. **The current book gets buried.** As the library grows, readers have to search for the book they're in the middle of.

---

## 3. Goals

**Goals**

1. The latest read is **easy to spot** on the Library page: first under the default sort. Showing it **separately** from other books isn't built (§5.2).
2. Opening a book (from the card or the library) always returns to **the same reading position**: with the same layout the visible page starts at the same paragraph and offset, including after the app is fully closed; after a font, orientation, or window size change, the last-read paragraph is on the visible page.
3. Progress is saved **automatically**, with no action from the reader.
4. Keep an accurate `readingFrontier`. Epic 2 doesn't read it right now (PRD 2.1 §5.4).

**Non-goals (this release)**

- Reading session history (duration, daily stats). (\*)
- Syncing the reading position across devices. (\*)
- Manual bookmarks and highlights. (\*)
- Several "Continue reading" cards at once. (\*)

## 5. Main Flow

### 5.1 User flow

```mermaid
flowchart LR
  A([Start: Revisit the app]) --> B[Library page<br/>latest read first]
  B --> C[Reading page<br/>exact same position]
  C --> D([End: Reading page])
```

| # | Screen | See | Do | System response |
|---|---|---|---|---|
| 1 | Library page | Books sorted by Latest Read by default, each with a progress bar | Tap the book | Reading page opens |
| 2 | Reading page | The same page as when last left: the same paragraph and sentence are on the visible page | Keep reading | Progress keeps being saved (§5.4) |

### 5.2 Latest Read rules

- **Latest Read** = the Latest Read sort in the library (PRD 1.2 §5.2): most recent `lastReadAt` first. Finished books are not left out.
- **Finished** = the reader has shown the book's last page, or `progress ≥ 0.99`, or chose Mark as Finished (PRD 1.2). Once set, `finishedAt` stays until Mark as Still Reading or Reset Progress.

**Not built, requirement kept (\*):** a **Continue reading** card at the top of the library, separate from the other books: large cover, title, author, current chapter, progress (%), time last read. It would show the unfinished book with the most recent `lastReadAt`, a "Reading" marker on that book in the list, and the next unfinished book when that one is removed or finished. `BookRecord.isContinueReading` exists, but nothing shows it.

### 5.3 Progress log (\*)

One `ReadingProgress` per book, stored in `Books/<bookID>/progress.json`.

| Field | Content | Purpose |
|---|---|---|
| `bookID` | Book ID | Key |
| `position.paragraph` | Global paragraph index (from `BookContent`) | Reading position independent of screen or font size |
| `position.charOffset` | Character offset in the paragraph (UTF-16) of the first word on the visible page | Exact position inside long paragraphs |
| `chapterIndex` | Chapter index | Fallback when a position is invalid |
| `progress` | 0–1, words before the position / total words | Progress bar in the library |
| `lastReadAt` | Timestamp of the last page change | Latest Read sort |
| `readingFrontier` | Index of the furthest sentence ever shown on screen. Pre-rendered or prefetched pages that are not visible do not count. The reader shows one page at a time, also in landscape. | Kept for later. Epic 2 doesn't read it right now (PRD 2.1 §5.4). |
| `finishedAt` | Timestamp the book was finished, or empty | Full progress bar in the library |

`lastOpenedAt` isn't built. Opening a book without turning a page doesn't change the Latest Read order.

### 5.4 Saving and restoring the position

**Saving**
- On every page change: update `position`, `chapterIndex`, `progress`, `lastReadAt`; `readingFrontier = max(readingFrontier, last sentence on the visible page)`. Disk writes run in the `ProgRepo` actor and are coalesced (one write at a time, always the latest state), so a force quit loses at most the last page turn.
- When the app goes to the background or the reader taps Back: write immediately.
- Writes are atomic so the file isn't corrupted by a force quit.

**Restoring**
1. Load `ReadingProgress`; if there is none, open at the start of the book.
2. Paginate for the current screen size and font.
3. Find the page containing `(position.paragraph, position.charOffset)` and show it.
4. If the position is invalid (for example `BookContent` was rebuilt and paragraphs changed), open at the start of chapter `chapterIndex` and log `restored_ok = false`.

**Relation to Jump to Passage (Epic 2)**
- When the reader jumps to a passage, the saved position follows the page being shown, while `readingFrontier` doesn't move backwards.
- The origin for "Return to Reading" is stored by Epic 2 in `BookState.returnPosition`, so that button still works after the app reopens.

### 5.5 Reading page

The reading page has features no story covered before. They are recorded here so the PRD matches the app.

| Feature | Behaviour |
|---|---|
| **Page** | One page at a time, also in landscape. Swipe, or tap a page edge, to turn the page. Pages are laid out with TextKit (`PagerSvc`). |
| **Controls** | Top: Back, book title, chapter title. Bottom: page label and "…" menu. Turning the page hides the buttons, and tapping the middle of the page shows or hides them. The text never moves. |
| **Page label** | "Page N", or "Page N of M" while the controls are shown |
| **Contents** | "…" → Contents: chapter list with start pages; tap to go there |
| **Search in Book** | "…" → Search in Book: exact text search of the whole book, with chapter, snippet, and page. Tapping a result opens the page with the match highlighted. Recent searches are saved per book (up to 10). Results can include pages the reader hasn't reached. |
| **Theme & Settings** | "…" → Theme & Settings: text size (11 sizes, 17 to 56 pt), line spacing (80% to 250%), brightness, and six themes (Original, Quiet, Paper, Bold, Calm, Focus). One set for the whole app, saved in `reading-settings.json`. |
| **Book can't open** | "Can't Open Book" |

### 5.6 Components (MVVM)

| Layer | Component | Responsibility |
|---|---|---|
| Model | `ProgRepo` | Saving and loading `ReadingProgress`, coalesced and atomic writes, finished and reset |
| Model | `ReadingProgressCalculator` (pure rule) | Position, progress, finished, and the rule `max(readingFrontier, last visible sentence)` |
| Model | `ProgressCtrl` | Restore and save progress; logs the §4.5 events through `EventSvc` |
| Model | `PagerSvc` | Pages for the current text settings and viewport |
| Model | `ReaderCtrl` | Book content, current position, pages, page counts, search, position ↔ page |
| Model | `ReaderStateCtrl` | Reading settings, brightness, return position, recent searches |
| ViewModel | `ReaderVM` | State: pages, shown page, labels, controls, sheets, menu. Intents: `onAppear(viewport:)`, `viewportChanged(_:)`, `pageChanged(_:)`, `pageCenterTapped()`, `backTapped()`, `appBackgrounded()`, `appForegrounded()`, `chapterTapped(_:)`. |
| ViewModel | `ReaderSettingsVM`, `SearchVM` | Theme & Settings; search and recent searches |
| View | `ReaderView`, `PageTurnView`, `PageTextView`, `ReaderMenuView`, `ContentsView`, `SearchView`, `ThemeSettingsView` | Layout from §5.5; every action calls a ViewModel intent |

The shared data model is in PRD 1.0 §3.

## 8. Open Questions & Risks

1. **Continue reading card.** Not built; the Latest Read sort does part of the job. Decide whether the card is still needed for the demo. The sticky note asks for the book to be easy to notice and separable from other books. (\*)
2. **Progress log contents (TBD on the sticky note).** The fields in §5.3 need confirmation, especially whether to keep session history for other metrics.
3. **`readingFrontier` has no reader.** It is saved on every page turn but nothing uses it now. Keep it for a later feature, or remove it. (\*)
4. **Search can spoil.** Search in Book shows matches from pages the reader hasn't reached. PRD 0.0 lists this as a problem with other apps. Decide whether to limit it. (\*)
5. **Definition of "finished".** Books with long back matter (notes, glossary) may never reach the last page. Test whether the 0.99 threshold is enough. (\*)
6. **Re-parsing changes paragraph indexes.** If the parser is updated, an old `position.paragraph` can shift. `BookContent` has a parser version, but there is no position migration. (\*)
7. **Own paginator (decided).** `PagerSvc` is built in-house (Index §6), so pagination, text changes, and iPad window changes are our responsibility; they are covered by AC-1.3-03 and AC-1.3-04. (\*)
