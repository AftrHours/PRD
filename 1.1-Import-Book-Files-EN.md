## 1. Feature Name

**Import Book Files**

Readers import `.epub` books through Apple's native document picker. The app reads the title and author, copies the file, and lists the book. When the book opens, the app turns it into structured text (chapters, paragraphs, sentences), so it is readable and ready for the Reference Passage feature to analyse.

**User story**

> As a **reader**, I want to **import book files into the application** so that I know **the system can process the book**.

---

## 2. Problem

1. **Reference features need processable text.** The context resolution features (Epic 2) only work once a book is in the app as structured text. Readers need a clear way to import and to know whether the book was processed successfully.
2. **Unsupported formats are confusing.** Without clear error messages, readers don't know why a file failed to open (DRM, damaged file, another format).
3. **Importing must not make the app feel heavy.** Parsing long books and running NLP analysis takes time; if it runs in the foreground, the app feels stuck.

---

## 3. Goals

**Goals**

1. Readers can import `.epub` through Apple's native document picker in **≤ 3 taps**. (\*)
2. The book is **readable right after import**; underline analysis runs in the background without making the UI stutter.
3. Files outside the supported format are rejected with a **clear, actionable message**. Today only unreadable files are caught, with a general message (§5.4).
4. All files and book data are stored and processed **on-device**.

**Non-goals (this phase)**

- **PDF** (including text-layer PDFs and scanned PDFs / OCR). Planned for a later phase.
- Other formats (for example `.mobi`, `.azw`, `.txt`, `.docx`). (\*)
- DRM-protected EPUBs and books purchased in Apple Books.
- Importing from web links, the clipboard, the Share sheet, or "Open in". Import is through the document picker only. (\*)
- Editing book metadata (title, author, cover). (\*)

## 5. Main Flow

### 5.1 User flow

```mermaid
flowchart LR
  A([Start: Open App]) --> B[Library page]
  B --> C[Document picker]
  C --> D{File can be read?}
  D -- No --> E[Alert: Couldn't import EPUB] --> B
  D -- Yes --> F[Library page<br/>new book first]
  F --> G([End: Import book finished])
```

| # | Screen | See | Do | System response |
|---|---|---|---|---|
| 1 | Library page | **+** button at the top right | Tap **+** | Document picker opens full screen |
| 2 | Document picker | Apple's native document picker with the user's files (Files, iCloud Drive) | Pick one or more files | Only EPUB files can be picked; other formats (including `.pdf`) are greyed out |
| 3a | Library page | Alert "Couldn't import EPUB" with the system's message | Tap OK | Back to Library page. Books imported before the failure stay; the rest aren't tried. |
| 3b | Library page | The new book first in the library, with its cover, title, and author | Can tap the book; can tap **+** again | The book stays first until the reader changes the sort |

### 5.2 Alternative flows

- **A1. Picker cancelled:** the picker closes and the Library page is unchanged.
- **A2. Importing several files at once:** the picker allows multi-select, and files are imported in order. The first failure stops the rest, with one alert.
- **A3. Book already in the library (not built):** the same file is imported again as a second book. Requirement kept: "Already in your library" with an "Open" button. (\*)
- **A4. App closed during import (not built):** there is no resume. Requirement kept. (\*)
- **A5. Non-English book:** the book is imported and readable as usual. The app doesn't detect or store the language (PRD 2.1 A6).

### 5.3 System flow: ingestion

```mermaid
flowchart TD
  A[Document picker: .epub file copied by the system] --> B[EPUBKit reads title and author]
  B -- Fails --> X[Alert]
  B --> C[New UUID; copy to Books/id/book.epub]
  C --> D[BookRecord added to library.json]
  D --> E[Library reloads; cover read from the EPUB]
  E --> F[Reader opens the book]
  F --> G[EPUBKit: chapters and paragraphs<br/>NLTokenizer: sentences]
  G --> H[BookContent in memory: book is readable]
  H --> I[Epic 2 analysis in the background]
```

**Step 1: Pick and copy.** `EPUBDocumentPicker` wraps `UIDocumentPickerViewController` (`forOpeningContentTypes: [.epub]`, `asCopy: true`, multi-select). `LibRepo.importBook` reads the metadata first, so a file EPUBKit can't read stops here and nothing is copied. If the title is empty, it comes from the file name; if the author is empty, it shows "Unknown Author".

**Step 2: EPUB parsing (when the book opens).** `EPUBParseSvc` calls `EPUBKit`: `META-INF/container.xml` → OPF → metadata, manifest, spine, cover (the EPUB 3 `cover-image` property or the EPUB 2 `cover` meta tag). Text comes from the spine in reading order, split into chapters by the table of contents that the OPF's `spine toc` points to (`toc.ncx`). Text before the first entry goes into a chapter named after the book. An EPUB 3 `nav` file isn't read, so a book with no `toc.ncx` becomes one long chapter.

**Step 3: Structure.** Paragraphs are split into sentences with `NLTokenizer`, and every paragraph and sentence gets a global index. No-break spaces after "Mr." and "Dr." are treated as plain spaces, so they don't end a sentence. The result is `BookContent` with `parserVersion` 1, kept in memory by `BookContentRepo`. A book with no chapters throws `ContentError.unreadable`.

**Step 4: Sample books.** Five public-domain EPUBs are bundled in the app and listed in `BookRecord.samples`. They skip Step 1. Little Women starts at a mock 30% until the reader has progress of their own.

> **Note for the PDF phase:** `BookContent` is designed to be format-independent, so a future PDF parser only needs to produce the same structure, with no changes to 1.2, 1.3, or Epic 2. (\*)

### 5.4 Error handling

**Built today**

| Condition | What the reader sees | Action |
|---|---|---|
| EPUBKit can't read the file, or a file operation fails, during import | Alert "Couldn't import EPUB" with the system's message | OK |
| Failure while removing or sharing a book | Alert "Something went wrong" (PRD 1.2) | OK |
| Parsing fails when the book opens | Reading page shows "Can't Open Book" | Back |

Only two content errors exist in code: `ContentError.notFound` and `ContentError.unreadable`.

**Not built, requirement kept (\*)**

| Code | Condition | User-facing message | Action |
|---|---|---|---|
| `unsupported_format` | File isn't a real EPUB (for example a renamed extension) | "This file isn't an EPUB. Choose a .epub file." | Choose another file |
| `drm_protected` | DRM-encrypted EPUB. An `encryption.xml` that only obfuscates fonts is not DRM. | "This book is copy-protected (DRM) and can't be opened. Try a DRM-free EPUB." | OK |
| `corrupted` | ZIP/OPF damaged or unreadable | "This file seems damaged and can't be opened." | Choose another file |
| `empty` | No chapter text | "This book has no readable text." | OK |
| `too_large` | Size above the limit (200 MB) | "This file is too large (max 200 MB)." | OK |
| `duplicate` | Same hash as a book in the library | "Already in your library." | Open |
| `storage_full` | Device storage full while copying | "Not enough storage to add this book." | OK |
| `access_denied` | File can't be accessed | "We couldn't access this file. Make sure it's downloaded and try again." | Choose another file |

### 5.5 Components (MVVM)

| Layer | Component | Responsibility |
|---|---|---|
| Model | `LibRepo` | Reads metadata, copies the file, writes `library.json` |
| Model | `LibCtrl` | Import use case for the ViewModel |
| Model | `EPUBParseSvc` + `EPUBKit` | Metadata, cover, chapters; `BookContent` with sentences |
| Model | `BookContentRepo` | One parse per book, kept in memory; covers; finds the imported or bundled file |
| ViewModel | `LibVM` | `importFiles(_:)`, `importError`, `dismissImportError()`, pins the newest import to the top |
| View | `LibView` (**+** button, alert), `EPUBDocumentPicker` | Every action calls a `LibVM` intent |

The data model and storage are in PRD 1.0 §3.

## 8. Open Questions & Risks

1. **EPUB variety.** EPUBs from different sources (Project Gutenberg, Standard Ebooks, publishers) have different XHTML structures, for example inline footnotes or chapters split across several files. A test set of EPUBs from several sources is needed early. (\*)
2. **File size limit.** 200 MB is a proposal; illustrated EPUBs can be large. Needs testing. (\*)
3. **Validation is missing.** A file that opens as a ZIP with readable metadata passes, whatever is inside. DRM books will import and then fail or show garbled text. Decide whether the §5.4 checks are required for the demo. (\*)
4. **EPUB 3 chapters.** `nav` isn't read, and a single long chapter affects Reference Passage, which searches one chapter at a time. (\*)
5. **Other import sources.** Readers often use the Share sheet and "Open in" to move books from other apps; decide whether these come after the demo. (\*)
6. **PDF phase.** When PDF is developed, it needs its own PRD for the PDF parser (text extraction, headers/footers, chapter detection, scanned PDFs). (\*)
7. **Own parser (decided).** The EPUB parser (`EPUBKit`) is built in-house (Index §6) so Epic 2 gets sentence-level positions. A third-party toolkit can be reconsidered later. (\*)
