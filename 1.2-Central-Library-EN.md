## 1. Feature Name

**Central Library**

One page that shows the sample books and every imported book in grid or list mode, can be sorted, and is the entry point to the reading page. From here readers can also add books (PRD 1.1), mark it finished, reset its progress, and remove it.

**User story**

> As a **reader**, I want a **central library displaying all my imported books** so that I can **easily browse and select what to read**.

---

## 2. Problem

1. **Books are scattered.** EPUB files live in Files, iCloud Drive, or downloads. Without a central library, readers have to find the file again every time they want to read.
2. **A growing collection is hard to manage.** Without clear ordering and view modes, readers struggle to find a given book, and books they no longer need fill up storage.
3. **An empty page gives no direction.** A new user opening an empty library needs to know what to do first.

---

## 3. Goals

**Goals**

1. The library shows every book in **grid or list** mode, with its reading progress clearly visible.
2. Books can be **sorted** by Title, Author, Date Added, Latest Read, or Read Progress.
3. Readers open a book with **one tap**.
4. Books can be **removed** with all their data, after confirmation.
5. An empty library tells the reader how to add a book.

**Non-goals (this release)**

- Collections/shelves and tags. (\*)
- Editing book metadata (title, author, cover). (\*)
- Removing several books at once. (\*)

## 5. Main Flow

### 5.1 User flow

```mermaid
flowchart LR
  A([Start: Open App]) --> B[Library page<br/>grid / list + sorting]
  B --> C{Any books?}
  C -- No --> D[Empty state: No books yet] --> B
  C -- Yes --> E[Tap a book, or open its menu]
  E --> F([End: Reading page])
```

| # | Screen | See | Do | System response |
|---|---|---|---|---|
| 1 | Library page | Top bar: "Search Book" field (no action yet) and **+**. Header: "Library", grid/list button, sort button. Then the books. | – | – |
| 2 | Library page (first launch) | 5 sample books: Little Women, Anne of Green Gables, Moby Dick, Pride and Prejudice, The Adventures of Sherlock Holmes | – | Bundled in the app |
| 3 | Library page (grid, default) | Each cell: cover, progress bar, title, author, "…" menu. 3 columns on iPad and 2 on iPhone, in every orientation. | Switch to list | Mode changes until the app restarts |
| 4 | Library page (list) | Each row: small cover, progress bar, title, author, "…" menu | Switch to grid | Mode changes until the app restarts |
| 5 | Library page (sorting) | Sort menu: **Title**, **Author**, **Date Added**, **Latest Read** (default), **Read Progress**, with a check on the active option | Pick an order | Books reorder (§5.2) until the app restarts |
| 6 | Library page | Books | Tap a book | Reading page opens at the last position (PRD 1.3), or at the start if never read |
| 7 | Library page | "…" menu on a book: **Mark as Finished** / **Mark as Still Reading**, **Reset Progress**, **Remove** | Choose one | §5.3 and §5.4 |
| 8 | Library page (empty) | "No books yet" and "Tap the + button to import an EPUB". Only when every sample book is removed and nothing is imported. | Tap **+** | Document picker (PRD 1.1) |

### 5.2 Sorting rules

| Sort | Order |
|---|---|
| Latest Read (default) | Latest `lastReadAt` first; never-read books last |
| Title | A–Z, case-insensitive, by the full title |
| Author | A–Z, case-insensitive, by the full author text |
| Date Added | Newest first. Sample books count as oldest. |
| Read Progress | Highest progress first. A finished book counts as 100%. |

A newly imported book stays first until the reader changes the sort.

**Not built, requirement kept (\*):** ignoring leading articles in Title, sorting Author by last name, a "Recent" sort based on `lastOpenedAt`, and tie-breakers.

### 5.3 Book menu and alternative flows

- **A1. Share Book (removed on `dev`):** the menu no longer has it.
- **A2. Mark as Finished / Still Reading:** sets or clears `finishedAt` and keeps the reading position. A finished book shows a full progress bar.
- **A3. Reset Progress:** sets the position and frontier back to the start and clears `finishedAt`. It is saved as a 0% record, so a sample book doesn't return to its mock progress. There is no confirmation.
- **A4. Removal cancelled:** the confirmation dialog closes with no change.

**Not built, requirement kept (\*):** book statuses in the library: `preparing` ("Still preparing this book"), analysis still running, and `failed` with an error icon (PRD 1.0 §3.2).

### 5.4 Removing a book

1. The reader chooses **Remove** from the "…" menu.
2. Confirmation dialog: "Remove Book?", "'[title]' and your reading progress will be removed from this iPad." with **Remove** (destructive) and **Cancel** buttons.
3. Once confirmed:
   - **Imported book:** its `BookRecord` is removed from `library.json` and its `Books/<bookID>/` folder is deleted (EPUB, `ReadingProgress`, `BookState`, saved underlines).
   - **Sample book:** its ID is added to `hidden-samples.json`. It lives in the app bundle, so nothing is deleted, and its reading files stay. There is no way to bring it back in the app.
4. If removal fails: alert "Something went wrong".

### 5.5 Components (MVVM)

| Layer | Component | Responsibility |
|---|---|---|
| Model | `LibRepo` | Loads samples + imported books; imports; removes and hides books |
| Model | `LibrarySorter` | Sorting rules from §5.2 as a pure function, with a pinned new book |
| Model | `LibCtrl` | Library use cases; merges `ReadingProgress` into each book; finished and reset through `ProgRepo`; remove also forgets the parse |

Intents: `onAppear()`, `toggleViewMode()`, `sortChanged(_:)`, `bookTapped(_:)`, `finishedToggled(_:)`, `resetProgressTapped(_:)`, `removeTapped(_:)`, `removeConfirmed()`, `removeCancelled()`. ## 8. Open Questions & Risks

1. **Save view mode and sort?** They reset at each launch. The first PRD required saving them. (\*)
2. **Removed books leave their underlines.** They stay in `Underlines/<fingerprint>/` and in the reader's iCloud after removal. Decide whether removal should delete them, or keep them so a re-import is instant.
3. **Sample books.** They mix mock data into the library (Little Women's 30%), and a removed sample can't be brought back. Decide whether they stay after the demo. (\*)
4. **Search bar.** It filters the library by title and author as the reader types.
5. **Reset Progress has no confirmation**, and it can't be undone. (\*)
6. **Layouts.** The grid has a fixed 3 columns on iPad and 2 on iPhone. The remove dialog says "from this iPad" on iPhone too. Mac layout is **TBD**. (\*)
7. **Default sort.** Latest Read is the default because it brings the current book to the top; confirm with usability testing. (\*)
8. **Undo removal.** Removal is permanent; decide whether a short undo (for example a 5-second "Undo" toast) comes after the demo. (\*)
9. **Multi-device library (PRD 1.4).** The library lists the same books on every device on one iCloud account. What happens when a book is removed on one device is still open (PRD 1.4 §5.5).
