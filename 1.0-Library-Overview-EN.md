## 1. Epic

> As a **reader**, I need a **centralized library system to import text documents, manage my book collection, and quickly access my latest read**, so that I have **seamless navigation before interacting with the context resolution features.**

### 1.1 Story map

| Story | Document | User story | Main output |
|---|---|---|---|
| **1.1 Import Book Files** | `1.1-Import-Book-Files-EN.md` | As a reader, I want to import book files into the application so that I know the system can process the book. | `BookRecord` and the book's EPUB file on the device |
| **1.2 Central Library** | `1.2-Central-Library-EN.md` | As a reader, I want a central library displaying all my imported books so that I can easily browse and select what to read. | Library page: sample books, grid/list, sort, open, book menu, remove |
| **1.3 Latest Read** | `1.3-Latest-Read-EN.md` | As a reader, I want to see my latest read so that I can easily find the book I have imported. | `ReadingProgress` (reading position + reading frontier) and the reading page. The Continue reading card is not built. |

### 1.2 Relation to Epic 2 (Reference Passage)

| Epic 1 provides | Epic 2 uses it for |
|---|---|
| `BookContent` from `EPUBParseSvc` | Each chapter goes to UnderlineEngine through `ChapterInputMapper`; Epic 2 never reads book files directly |
| `BookContent.parserVersion` | Saved underlines are worked out again when it changes |
| Reading page and `PagerSvc` (PRD 1.3) | Drawing underlines and highlights on the exact text, and turning a passage into a page |
| The first page shown (PRD 1.3) | The starting point of background analysis, so the reader's chapter goes first |
| `ReadingProgress.readingFrontier` (PRD 1.3) | Nothing right now. The read boundary (PRD 2.1 §5.4) doesn't need it. |

Suggested build order: 1.1 → 1.2 → 1.3 → 2.1. (\*)

## 3. Shared data model

### 3.1 Data ownership

Every field has **one writer**. Other documents read it and don't keep their own copy.

| Data | Owner | Key fields | Read by |
|---|---|---|---|
| `BookRecord` | PRD 1.1 (creates), PRD 1.2 (removes), through `LibRepo` | id, title, author, dateAdded. `progress` and `lastReadAt` are filled in from `ReadingProgress` when the library loads. `isContinueReading` is set but nothing shows it. | 1.2, 1.3 |
| `BookContent` | PRD 1.1, through `BookContentRepo`. Parsed from the EPUB **when a book opens** and kept in memory, not on disk. | chapters, paragraphs, sentences, parserVersion | 1.3 (position, pages), 2.1 |
| `StoredUnderlines` | PRD 2.1 only (can be rebuilt without touching `BookContent`) | chapter, engineVersion, parserVersion, usedModel, underlines, dropped | 2.1 |
| `ReadingProgress` | PRD 1.3 | bookID, position (paragraph, charOffset), chapterIndex, progress, lastReadAt, readingFrontier, finishedAt | 1.2 (progress bar, sort, finished) |
| `BookState` | Reader (PRD 1.3 and 2.1) | returnPosition, recentSearches | 1.3, 2.1 |
| `ReadingSettings` | PRD 1.3 | textSizeIndex, lineSpacingPercent, theme. One set for the whole app. | 1.3 |
| Hidden sample IDs | PRD 1.2 | Sample books the reader removed | 1.2 |

The library's view mode and sort are **not saved**. They are kept in `LibVM` and reset when the app restarts.

### 3.2 Book status lifecycle

**The app has no book status.** Import reads the metadata and copies the file, and the book is then in the library and can be tapped. The text is parsed when the book opens.

| State | Shown in the library | Can be opened? |
|---|---|---|
| In the library | Cover, title, author, progress bar | Yes, unless parsing fails: the reading page then shows "Can't Open Book" |

**Not built, requirement kept (\*):** `preparing`, `ready`, and `failed(error_code)` statuses, a "Preparing…" label, an analysis indicator in the library, and marking non-English books. See PRD 1.1 §5.4 and PRD 1.2 §5.3. Underline progress shows only on the debug screen (PRD 2.1 §5.5).

### 3.3 Storage

```
Application Support/
├── reading-settings.json        // ReadingSettings (PRD 1.3)
└── Books/
    ├── library.json             // [BookRecord], imported books only
    ├── hidden-samples.json      // sample books the reader removed (PRD 1.2)
    └── <bookID>/
        ├── book.epub            // the imported file; sample books stay in the app bundle
        ├── progress.json        // ReadingProgress (PRD 1.3)
        ├── state.json           // BookState
        └── underlines/
            └── chapter-N.json   // StoredUnderlines (PRD 2.1), can be rebuilt
```

Covers aren't stored: each cover is read from the EPUB and kept in memory as a thumbnail. Removing an imported book (PRD 1.2) deletes its `Books/<bookID>/` folder and its `BookRecord` entry. Removing a sample book only hides it, and its reading files stay.

### 3.4 App architecture (MVVM)

The app is built with MVVM, with one folder per feature and one folder per layer inside it. `EReader/iRead/ARCHITECTURE.md` is the source for this section.

| Folder | Contains |
|---|---|
| `App/Book` | Per-book data shared by every feature: `BookRecord`, `BookContent`, `Page`, `ReadingProgress`, `BookContentRepo`, `ProgRepo`, `EPUBParseSvc` |
| `App/Library` | Library page: list, sort, grid/list, EPUB import |
| `App/Reader` | Reading page: paging, progress, settings, search, contents, reference cards |
| `App/Analysis` | Underlines and reference passages, through the UnderlineEngine package |
| `App` | `iReadApp`, `AppNav` (route: library or reader), `AppContainer` (the only type that builds everything) |
| `Packages/EPUBKit` | Reads EPUB files, on ZIPFoundation |

Dependencies point down: `View → VM → Ctrl → Repo / Svc → Models`. `Rules` can be called from anywhere. Library and Reader use Book; Reader uses Analysis; Analysis uses Book.

| Story | Folder | ViewModels |
|---|---|---|
| 1.1 Import Book Files | `Library`, `Book` | `LibVM` |
| 1.2 Central Library | `Library` | `LibVM` |
| 1.3 Latest Read | `Reader`, `Book` | `ReaderVM`, `ReaderSettingsVM`, `SearchVM` |
| 2.1 Reference Passage | `Analysis`, `Reader` | `ReferenceVM` |

The app has no test target. Acceptance criteria are checked by hand in the app.

### 3.5 Naming

- **Suffixes by role:** `VM`, `Ctrl`, `Svc`, `Repo`, `View`. Pure logic with no I/O or state goes in a `Rules/` folder, with a plain noun name (`LibrarySorter`, `ReadingProgressCalculator`).
- **Data types** keep full names (`BookRecord`, `ReadingProgress`).
- **Intents** are named after the user action in the past tense (`bookTapped(_:)`, `removeConfirmed()`); lifecycle intents are `onAppear()`.
- **Events** use the format `<PREFIX>_<Name>_<Type>`: `RD` is in use; `LB`, `RF`, and `SY` are planned.
- **Tuning values** sit in a `…Knobs` enum at the top of the file that uses them.

## 4. Shared rules

| Rule | Target |
|---|---|
| Processing | All files and book data are stored and processed on-device |
| Network calls containing book content | 0 |
| Main thread | No parsing, analysis, or large file I/O on the main thread |
| Crash-free sessions | ≥ 99.5% (\*) |
| Event convention | `<PREFIX>_<Name>_<Type>`; RD = reader (in use); LB = library, RF = reference lookup, SY = symbols (planned) |
| Event privacy | No book title, content, or file name; only IDs, format, language code, error codes, and numbers |
| Event logging | Local (OSLog). Only `RD_Position_Restore` and `RD_Book_Finished` are logged today. An export option and sending to a server (opt-in) are not built. (\*) |

## 6. Open Questions & Risks (cross-story)

1. **Requirements not built.** The first PRD asked for book statuses, import errors, saved library settings, and a Continue reading card. The app has none of these. They stay in the story PRDs with the status "Not built". Decide for each whether it stays in the demo. (\*)
2. **Platform.** Decided: this release targets **iPadOS only**. iPhone (iOS) and macOS are **TBD** and need their own decision. `project.yml` still lists iPhone as a device family (`TARGETED_DEVICE_FAMILY: "1,2"`). (\*)
3. **PDF in a later phase.** `BookContent` is format-independent, so a future PDF parser can be added without changing 1.2, 1.3, or Epic 2. The PDF phase needs its own PRD. (\*)
4. **Parsing on every open.** `BookContent` isn't saved, so each open parses the EPUB again. Measure this on a long book on iPad. (\*)
5. **Progress log contents** (TBD on the sticky note): the fields in PRD 1.3 §5.3 need team confirmation.
