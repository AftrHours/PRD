## 1. Epic

> As a **reader**, I need a **centralized library system to import text documents, manage my book collection, and quickly access my latest read**, so that I have **seamless navigation before interacting with the context resolution features.**

### 1.1 Story map

| Story | Document | User story | Main output |
|---|---|---|---|
| **1.1 Import Book Files** | `1.1-Import-Book-Files-EN.md` | As a reader, I want to import book files into the application so that I know the system can process the book. | `BookRecord` and `BookContent` (structured text + language) |
| **1.2 Central Library** | `1.2-Central-Library-EN.md` | As a reader, I want a central library displaying all my imported books so that I can easily browse and select what to read. | Library page: empty state, list/grid, sort, open, remove |
| **1.3 Latest Read** | `1.3-Latest-Read-EN.md` | As a reader, I want to see my latest read so that I can easily find the book I have imported. | Continue reading card and `ReadingProgress` (reading position + reading frontier) |

### 1.2 Relation to Epic 2 (Reference Passage)

| Epic 1 provides | Epic 2 uses it for |
|---|---|
| `BookContent` from the EPUB parser (PRD 1.1) | Input for entity analysis; Epic 2 never reads book files directly |
| `BookRecord.language` (PRD 1.1) | Disabling reference features for non-English books (PRD 2.1 AC-2.1-17) |
| `ReadingProgress.readingFrontier` (PRD 1.3) | The anti-spoiler boundary (PRD 2.1 §5.4) |
| `ready` status (PRD 1.1) | The starting point for background analysis |

Suggested build order: 1.1 → 1.2 → 1.3 → 2.1. (\*)

## 3. Shared data model

### 3.1 Data ownership

Every field has **one owner**. Other documents read it and don't keep their own copy.

| Data | Owner | Key fields | Read by |
|---|---|---|---|
| `BookRecord` | PRD 1.1 (creates), PRD 1.2 (removes), PRD 2.1 (updates `analysisProgress` only) | id, title, author, format (epub), fileHash, fileSize, addedAt, lastOpenedAt, status, coverData, wordCount, chapterCount, language, analysisProgress | 1.2, 1.3, 2.1 |
| `BookContent` | PRD 1.1 (text structure); PRD 2.1 adds entities, mentions, relations | chapters, paragraphs, sentences; entities, mentions, relations, llmCache | 1.3 (position), 2.1 |
| `ReadingProgress` | PRD 1.3 | bookID, position (paragraph, charOffset), chapterIndex, progress, lastReadAt, readingFrontier, finishedAt | 1.2 (list progress), 2.1 (anti-spoiler) |
| `BookState` | PRD 2.1 | returnPosition, overrides (Wrong match), symbols, customNames | 2.1 |
| `LibrarySettings` | PRD 1.2 | viewMode (list / grid), sort (recent / title / author) | 1.2 |

### 3.2 Book status lifecycle

| Status | Meaning | Shown in the library | Can be opened? |
|---|---|---|---|
| `preparing` | File copied; parsing (PRD 1.1) running | Placeholder cover, "Preparing…" label with an indicator | No; tapping shows "Still preparing this book" |
| `ready` + `analysisProgress < 1` | Text ready; Epic 2 analysis running in the background | Cover, title, author, small analysis indicator | Yes; reference aids appear progressively |
| `ready` + `analysisProgress = 1` | Text and analysis done | Cover, title, author, reading progress | Yes |
| `failed(error_code)` | Parsing failed after the file was copied | Error icon, short message, "Remove" option | No |

Errors caught before a `BookRecord` exists (wrong format, DRM, and so on) never appear in the library; see PRD 1.1 §5.4.

### 3.3 Storage

```
Application Support/
├── library.json                 // [BookRecord], LibrarySettings
└── Books/<bookID>/
    ├── original.epub
    ├── content.json             // BookContent
    ├── progress.json            // ReadingProgress
    └── state.json               // BookState (Epic 2)
```

Removing a book (PRD 1.2) deletes the whole `Books/<bookID>/` folder and its `BookRecord` entry. (\*)

### 3.4 App architecture (MVVM)

The app is built with MVVM. The layers and rules below apply to every story.

| Layer | Target | Contains |
|---|---|---|
| Model | `ReaderCore` | Data from §3.1, services (import, library, progress, analysis, symbols), pure rules (sorting, spoiler filter) |
| ViewModel | `ReaderPresentation` | One `@Observable` class per screen or card: view state, intents named after user actions, analytics events |
| View | App (SwiftUI) | Layout and bindings only; every user action calls a ViewModel intent |

| Story | ViewModels |
|---|---|
| 1.1 Import Book Files | `BookImportViewModel` |
| 1.2 Central Library | `LibraryViewModel` |
| 1.3 Latest Read | `ContinueReadingViewModel`, `ReaderViewModel` (reading part) |
| 2.1 Reference Passage | `ReaderViewModel` (reference part), `ReferenceCardViewModel`, `SettingsViewModel` |

ViewModels are tested with fake Model services, so most acceptance criteria in 1.1–1.3 are verified without UI tests.

## 4. Shared rules

| Rule | Target |
|---|---|
| Processing | All files and book data are stored and processed on-device |
| Network calls containing book content | 0 |
| Main thread | No parsing, analysis, or large file I/O on the main thread |
| Crash-free sessions | ≥ 99.5% (\*) |
| Event convention | `<PREFIX>_<Name>_<Type>`; LB = library, RD = reader, RF = reference lookup |
| Event privacy | No book title, content, or file name; IDs, format, and numbers only |
| Event logging | Local (OSLog) with an export option for the demo and usability tests; sending to a server (opt-in) after launch (\*) |

## 5. Demo scope

### 5.1 Priorities per story

| Story | P0 (required for the demo) | P1 (should be in the demo) | P2 (after the demo) |
|---|---|---|---|
| **1.1** | Add book + document picker; EPUB import; background parsing; errors for wrong format, DRM, damaged file, no text; non-English books stay readable | Duplicate detection; multi-select; import resume | PDF support (including OCR for scanned PDFs); import from the Share sheet / "Open in" / links |

| **1.3** | Continue reading card; progress log; exact position restore (including after font/orientation changes) | Card rules when every book is finished or a book is removed | Reading session history |

### 5.2 End-to-end demo scenario (\*)

Files to prepare: one demo EPUB (a 5–8 chapter short story, also used by PRD 2.1), one public-domain novel EPUB, one DRM-protected EPUB, and one `.pdf` file (to show that PDFs can't be picked yet).

| # | Step | Story |
|---|---|---|
| 1 | Open the app for the first time → empty state with the "Add book" CTA | 1.2 |
| 2 | Tap the CTA → document picker; `.txt` and `.pdf` files are greyed out → pick the demo EPUB → "Preparing…", then ready within 2 seconds | 1.1 |
| 3 | Add book → DRM-protected EPUB → "This book is copy-protected (DRM)…" error | 1.1 |
| 4 | Add book → novel EPUB → appears with its cover, title, and author | 1.1 |
| 5 | Switch to grid; sort by Title, then Author | 1.2 |
| 6 | Open the demo EPUB, read to Chapter 3 → back to the library → Continue reading card (Chapter 3, progress) | 1.3 |
| 7 | Fully close the app, reopen, tap the card → the same paragraph shows | 1.3 |
| 8 | Continue with the Reference Passage scenario (PRD 2.1 §6.2 steps 2–7) in the demo EPUB | 2.1 |
| 9 | Back in the library, remove the novel EPUB → confirm → gone from the library | 1.2 |

**Target:** the scenario runs without errors 5 times in a row on iPad. (\*)

## 6. Open Questions & Risks (cross-story)

1. **Platform.** Decided: this release targets **iPadOS only**. iPhone (iOS) and macOS are **TBD** and need their own decision. The design references (Apple Books, Google Play Books) are iPhone layouts, so they must be adapted to iPad (larger canvas, landscape, Split View / Stage Manager, keyboard and pointer support). (\*)
2. **PDF in a later phase.** `BookContent` is format-independent (PRD 1.1 §5.3), so a future PDF parser can be added without changing 1.2, 1.3, or Epic 2. The PDF phase needs its own PRD. (\*)
3. **Progress log contents** (TBD on the sticky note): the proposed fields are in PRD 1.3 §5.3 and need team confirmation.
