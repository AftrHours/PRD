## 1. Epic

> As a **reader**, I need a **centralized library system to import text documents, manage my book collection, and quickly access my latest read**, so that I have **seamless navigation before interacting with the context resolution features.**

### 1.1 Story map

| Story | Document | User story | Main output |
|---|---|---|---|
| **1.1 Import Book Files** | `1.1-Import-Book-Files-EN.md` | As a reader, I want to import book files into the application so that I know the system can process the book. | `BookRecord` and `BookContent` (structured text + language) |
| **1.2 Central Library** | `1.2-Central-Library-EN.md` | As a reader, I want a central library displaying all my imported books so that I can easily browse and select what to read. | Library page: empty state, list/grid, sort, open, remove |
| **1.3 Latest Read** | `1.3-Latest-Read-EN.md` | As a reader, I want to see my latest read so that I can easily find the book I have imported. | Continue reading card and `ReadingProgress` (reading position + reading frontier) |

### 1.2 Relation to Epic 2 (Reference Passage)

| Epic 1 provides | Epic 2 uses it for |
|---|---|
| `BookContent` from the EPUB parser (PRD 1.1) | Input for entity analysis; Epic 2 never reads book files directly |
| `BookRecord.language` (PRD 1.1) | Disabling reference features for non-English books (PRD 2.1 AC-2.1-17) |
| `ReadingProgress.readingFrontier` (PRD 1.3) | The anti-spoiler boundary (PRD 2.1 §5.4) |
| `ready` status (PRD 1.1) | The starting point for background analysis |

Suggested build order: 1.1 → 1.2 → 1.3 → 2.1. (\*)

## 3. Shared data model

### 3.1 Data ownership

Every field has **one writer**. Other documents read it and don't keep their own copy. When a record has fields written by different stories, each field's writer is listed.

| Data | Owner | Key fields | Read by |
|---|---|---|---|
| `BookRecord` | PRD 1.1 (creates and writes every field except the two below), PRD 1.2 (removes), PRD 1.3 (writes `lastOpenedAt`, through `LibRepo`), PRD 2.1 (writes `analysisProgress`) | id, title, author, format (epub), fileHash, fileSize, addedAt, lastOpenedAt, status, coverFile, wordCount, chapterCount, language, analysisProgress | 1.2, 1.3, 2.1 |
| `BookContent` | PRD 1.1 only | chapters, paragraphs, sentences, parserVersion | 1.3 (position), 2.1 |
| `BookAnalysis` | PRD 2.1 only (can be rebuilt without touching `BookContent`) | entities, mentions, relations, analyzedParagraphs, isAnalysisComplete, analysisMethod, llmCache | 2.1 |
| `ReadingProgress` | PRD 1.3 | bookID, position (paragraph, charOffset), chapterIndex, progress, lastReadAt, readingFrontier, finishedAt | 1.2 (list progress), 2.1 (anti-spoiler) |
| `BookState` | PRD 2.1 | returnPosition, overrides (Wrong match), symbols, customNames | 2.1 |
| `LibrarySettings` | PRD 1.2 | viewMode (list / grid), sort (recent / title / author) | 1.2 |
| `ReferenceSettings` | PRD 2.1 | Apple Intelligence on/off, underline on/off, badge on/off | 2.1 |

### 3.2 Book status lifecycle

| Status | Meaning | Shown in the library | Can be opened? |
|---|---|---|---|
| `preparing` | File copied; parsing (PRD 1.1) running | Placeholder cover, "Preparing…" label with an indicator | No; tapping shows "Still preparing this book" |
| `ready` + `analysisProgress < 1` | Text ready; Epic 2 analysis running in the background | Cover, title, author, small analysis indicator | Yes; reference aids appear progressively |
| `ready` + `analysisProgress = 1` | Text and analysis done | Cover, title, author, reading progress | Yes |
| `failed(error_code)` | Parsing failed after the file was copied | Error icon, short message, "Remove" option | No |

Errors caught before a `BookRecord` exists (wrong format, DRM, damaged container, too large, and so on) never appear in the library. A book that fails later, while its text is extracted (for example no readable text), becomes `failed`; see PRD 1.1 §5.4.

Non-English books are never analysed (PRD 2.1 A7): PRD 2.1 sets their `analysisProgress` to 1 when it skips them, so no analysis indicator appears.

### 3.3 Storage

```
Application Support/
├── library.json                 // [BookRecord], LibrarySettings
├── settings.json                // ReferenceSettings (PRD 2.1)
└── Books/<bookID>/
    ├── original.epub
    ├── cover.jpg                // BookRecord.coverFile points here
    ├── content.json             // BookContent (PRD 1.1)
    ├── analysis.json            // BookAnalysis (PRD 2.1), can be rebuilt
    ├── progress.json            // ReadingProgress (PRD 1.3)
    └── state.json               // BookState (PRD 2.1)
```

Covers are stored as files, not inside `library.json`, so the library can load within 500 ms with 100 books (PRD 1.2 §4.4). Removing a book (PRD 1.2) deletes the whole `Books/<bookID>/` folder and its `BookRecord` entry. (\*)

### 3.4 App architecture (MVVM)

The app is built with MVVM. The layers and rules below apply to every story.

| Layer | Where in the code | Contains |
|---|---|---|
| Model | `SKModels` (data types from §3.1), `SKStorage` (`Repo/` with `*Repo` / `*RepoFile`, `Migration/`), and each feature's `<Feature>Logic` target (`Ctrl/`, `Svc/`, `Rules/`) | Data from §3.1, controllers (`ImportCtrl`, `RefCtrl`), services (`EPUBParseSvc`, `PagerSvc`, `LLMSvc`, `EmbeddingSvc`), repositories (`LibRepo`, `ProgRepo`), pure rules (`LibSorter`, `SpoilerFilter`, `FrontierRule`) |
| ViewModel | `VM/` folder of each feature's `<Feature>UI` target | One `@Observable` class per screen or card (`<Screen>VM`): view state, intents named after user actions, analytics events |
| View | `Views/` folder of `<Feature>UI`, and the app (SwiftUI) | Layout and bindings only (`<Screen>View`); every user action calls a ViewModel intent |

| Story | Feature package (\*) | ViewModels |
|---|---|---|
| 1.1 Import Book Files | `ImportFeat` | `ImportVM` |
| 1.2 Central Library | `LibFeat` | `LibVM` |
| 1.3 Latest Read | `ReaderFeat` | `ResumeCardVM`, `ReaderVM` (reading part) |
| 2.1 Reference Passage | `RefFeat` | `ReaderVM` (reference part), `RefCardVM`, `SettingsVM` |

Cross-feature protocols live in `SKContracts` (for example `Nav`) and test support in `SKTesting`. Test doubles are named `<Protocol>Fake`.

ViewModels are tested with fake Model services, so most acceptance criteria in 1.1–1.3 are verified without UI tests.

### 3.5 Naming (\*)

Names in the PRDs follow the naming guide (`05-NAMING.md`):

- **Suffixes by role:** `VM` (ViewModel), `Ctrl` (controller; implementation `<Name>CtrlLive`), `Svc` (service), `Repo` (repository; file implementation `<Data>RepoFile`), `View`. Pure logic with no I/O or state is a plain noun (`SpoilerFilter`, `LibSorter`, `FrontierRule`).
- **Short forms** are only these: `Lib`, `Ref`, `Prog`, `Sym`, `Link`, `Feat`, `Nav`, `Pager`, `Avail`, `Config`, `Resume`, and `SK` for the core packages. `Manager`, `Helper`, `Util`, and `Impl` are not used.
- **Data types** keep full names (`BookRecord`, `ReadingProgress`, `Entity`, `Mention`).
- **Intents** are named after the user action in the past tense (`bookTapped(_:)`, `removeConfirmed()`); lifecycle intents are `onAppear()` and `onDisappear()`.
- **Events** keep the PRD format `<PREFIX>_<Name>_<Type>`: `LB`, `RD`, `RF`, and for later features `SY` (symbols) and `LK` (links).
- **Errors** are `<Area>Error` (for example `ImportError`).

| Earlier name in drafts | Name now |
|---|---|
| `BookImportViewModel`, `LibraryViewModel`, `ContinueReadingViewModel`, `ReaderViewModel`, `ReferenceCardViewModel`, `SettingsViewModel` | `ImportVM`, `LibVM`, `ResumeCardVM`, `ReaderVM`, `RefCardVM`, `SettingsVM` |
| `BookImporter` | `ImportCtrl` / `ImportCtrlLive` |
| `EPUBParser`, `BookStructurer`, Cover cache | `EPUBParseSvc`, `StructureSvc`, `CoverCacheSvc` |
| `LibraryStore` with `LibraryRepository`, `SettingsRepository` | `LibRepo` / `LibRepoFile`, `SettingsRepo` / `SettingsRepoFile` |
| `LibrarySorter` | `LibSorter` |
| `ProgressTracker` | `ProgRepo` and `FrontierRule` |
| `Paginator` + `PositionResolver` | `PagerSvc` |
| `AnalysisScheduler`, `EntityResolver`, `EventDetector`, `RelationBuilder` | `AnalysisScheduleSvc`, `EntityResolveSvc`, `EventDetectSvc`, `RelationBuildSvc` |
| `ReferenceAssistant` | `LLMSvc`, `ModelAvailSvc`, and (for `NLEmbedding`) `EmbeddingSvc` |
| `ReferenceQuery` | `RefCtrl` |
| `ReferenceChunkingConfig` | `ChunkConfig` |
| `Navigating` | `Nav` |
| `ContinueReadingCard`, `LibraryView`, `BookGrid`, `BookList`, `ReferenceCardView`, `WrongMatchPicker` | `ResumeCardView`, `LibView`, `BookGridView`, `BookListView`, `RefCardView`, `WrongMatchPickerView` |

## 4. Shared rules

| Rule | Target |
|---|---|
| Processing | All files and book data are stored and processed on-device |
| Network calls containing book content | 0 |
| Main thread | No parsing, analysis, or large file I/O on the main thread |
| Crash-free sessions | ≥ 99.5% (\*) |
| Event convention | `<PREFIX>_<Name>_<Type>`; LB = library, RD = reader, RF = reference lookup; SY = symbols and LK = links for later features |
| Event privacy | No book title, content, or file name; only IDs, format, language code, error codes, and numbers |
| Event logging | Local (OSLog) with an export option for the demo and usability tests; sending to a server (opt-in) after launch (\*) |

### 5.2 End-to-end demo scenario (\*)

Files to prepare: one demo EPUB (a 5–8 chapter short story, also used by PRD 2.1), one public-domain novel EPUB, one DRM-protected EPUB, and one `.pdf` file (to show that PDFs can't be picked yet).

| # | Step | Story |
|---|---|---|
| 1 | Open the app for the first time → empty state with the "Add book" CTA | 1.2 |
| 2 | Tap the CTA → document picker; `.txt` and `.pdf` files are greyed out → pick the demo EPUB → "Preparing…", then ready within 2 seconds | 1.1 |
| 3 | Add book → DRM-protected EPUB → "This book is copy-protected (DRM)…" error | 1.1 |
| 4 | Add book → novel EPUB → appears with its cover, title, and author | 1.1 |
| 5 | Switch to grid; sort by Title, then Author | 1.2 |
| 6 | Open the demo EPUB, read to Chapter 3 → back to the library → Continue reading card (Chapter 3, progress) | 1.3 |
| 7 | Fully close the app, reopen, tap the card → the same paragraph shows | 1.3 |
| 8 | Continue with the Reference Passage scenario (PRD 2.1 §6.2 steps 2–7) in the demo EPUB | 2.1 |
| 9 | Back in the library, remove the novel EPUB → confirm → gone from the library | 1.2 |

**Target:** the scenario runs without errors 5 times in a row on iPad. (\*)

## 6. Open Questions & Risks (cross-story)
